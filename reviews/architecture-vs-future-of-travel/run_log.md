# run_log.md — 실행 기록

실행일: 2026-09-23. 조정자는 Claude Code 원격 세션이다.

## 1. 실제 실행 형태

- **하위 에이전트**: 조정자가 Claude Code의 Agent 도구로 general-purpose 하위 에이전트 7개를 만들었다.
  - 1차는 4개를 병렬로 돌렸다: R_A, R_B, J_1, J_2.
  - 2차는 3개를 병렬로 돌렸다: H_A, H_B, Q.
- **격리 방식**: 각 하위 에이전트는 상위 대화를 이어받지 않는 새 컨텍스트에서 시작했다. 받은 입력은 프롬프트에 넣은 지정 자료뿐이다. 프롬프트 전문은 `inputs/`에 있다.
  - 하위 에이전트는 기술적으로 파일과 웹 도구에 접근할 수 있었다. 대신 도구를 쓰지 말라는 지시를 받았다.
  - 작업 완료 알림에 기록된 도구 호출은 에이전트마다 1회였다. 보고서를 전달하는 호출이다. 각 보고서의 자기 신고('도구 사용: 없음')도 이와 맞는다.
  - 원문과 중간 보고서는 1·2차 작업이 모두 끝날 때까지 저장소가 아니라 세션 전용 임시 디렉터리에 두었다.
- **한계**
  - 모든 참여자는 같은 기반 모델이다. 그래서 독립성은 컨텍스트 분리 수준이고, 모델 다양성에서 오는 독립성은 없다.
  - 조정자는 1차 배정 전에 두 원문을 읽었다.
  - 2차 입력에서 잠정 종합 판정과 수치는 지웠다. 그러나 축별 논증 문장에는 판단 방향이 드러나 있어서, 방향 정보를 완전히 막지는 못했다.

## 2. 입력 배분

| 참여자 | 받은 입력 | 받지 않은 입력 |
|---|---|---|
| R_A | 공통 규칙, 정독 과업, 「건축」 원문과 번호 사본 | 「여행의 미래」, 평가 규약, 다른 보고서 |
| R_B | 공통 규칙, 정독 과업, 「여행의 미래」 원문 | 「건축」, 평가 규약, 다른 보고서 |
| J_1 | 공통 규칙, 비교 과업, 고정 규약, P=「건축」, Q=「여행의 미래」 | 정독 보고서, 다른 심사자 결과, P/Q 대응표 |
| J_2 | 위와 같음. 단 P=「여행의 미래」, Q=「건축」 | 위와 같음 |
| H_A, H_B, Q | 두 원문, 고정 규약, 익명화한 쟁점표, 익명화한 최초 보고서 4편 | 모델명, 다수/소수 표시, 잠정 종합 판정과 수치 |

- 2차 익명화 대응(조정자만 보유): 비교 보고서 X = J_2, 비교 보고서 Y = J_1.
- 익명화하면서 P/Q 표기는 작품 제목과 A/B 행 번호로 기계적으로 바꿨다(`tools/anonymize.py`).
