아니요, 괄호만 다른 게 아니에요. 진짜 차이는 만든 다음에 내용을 바꿀 수 있느냐 없느냐예요. 리스트는 되고 튜플은 안 돼요. 용어로는 리스트가 가변(mutable), 튜플이 불변(immutable)이에요.

```python
nums = [1, 2, 3]
nums[0] = 10       # 됨
nums.append(4)     # 됨

point = (1, 2)
point[0] = 10      # TypeError
point.append(3)    # AttributeError
```

튜플에는 `append`나 `sort` 같은 메서드가 아예 없고, 있는 건 `count`와 `index` 두 개뿐이에요.

이 차이가 제일 크게 드러나는 데가 딕셔너리 키랑 세트예요. 키나 세트 원소로 쓰려면 해시값이 변하지 않아야 하는데, 내용이 바뀔 수 있는 리스트는 아예 해시가 안 되게 막혀 있거든요. 그래서 `{(2, 3): "X"}`는 되는데 `{[2, 3]: "X"}`는 `TypeError`가 나요. 좌표 같은 걸 키로 삼을 때 튜플을 쓰는 이유가 이거예요.

다만 튜플이 못 바뀐다는 건 각 칸에 어떤 객체가 들어 있는지가 고정된다는 뜻이지, 그 객체 속까지 못 건드리게 막아 준다는 뜻은 아니에요. `t = (1, [2, 3])`일 때 `t[1] = [5]`는 에러지만 `t[1].append(4)`는 그냥 돼요. 이렇게 안에 리스트가 든 튜플은 해시도 안 돼서 딕셔너리 키로 못 써요.

쓰임새에도 관례가 있어요. 리스트는 같은 종류의 것을 여럿 모아 두고 늘렸다 줄였다 할 때(회원 목록, 점수 기록), 튜플은 자리마다 뜻이 정해진 한 덩어리를 다룰 때(`(x, y)` 좌표, `(이름, 나이)`) 써요. 튜플이 메모리를 조금 덜 쓰고 만드는 속도도 약간 빠르긴 한데, 그 정도 차이 때문에 고를 일은 거의 없어요.

그리고 괄호 얘기가 나왔으니 말인데, 사실 튜플을 만드는 건 괄호도 아니에요. 쉼표예요.

```python
a = (1)     # 그냥 정수 1
b = (1,)    # 원소 하나짜리 튜플
c = 1, 2    # 괄호 없어도 튜플
```

괄호가 꼭 있어야 하는 건 빈 튜플(`()`)을 만들 때랑, 함수 인자처럼 쉼표가 원래 다른 역할을 하는 자리 정도예요. `f(1, 2)`는 인자 두 개를 넘기는 거고, `f((1, 2))`는 튜플 하나를 넘기는 거예요. `return x, y`도 값을 두 개 돌려주는 것처럼 보이지만 실은 튜플 하나를 돌려주는 거고요.
