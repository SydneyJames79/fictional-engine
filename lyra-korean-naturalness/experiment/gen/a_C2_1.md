아니요, 괄호는 겉모습이고 진짜 차이는 만든 뒤에 바꿀 수 있느냐 없느냐예요. 리스트는 가변(mutable)이라 원소를 고치고 더하고 뺄 수 있고, 튜플은 불변(immutable)이라 한번 만들면 그대로예요.

```python
nums = [1, 2, 3]
nums[0] = 100      # OK
nums.append(4)     # OK

point = (1, 2, 3)
point[0] = 100     # TypeError: 'tuple' object does not support item assignment
```

나머지 차이는 거의 다 여기서 따라 나와요.

- **딕셔너리 키·세트 원소:** 튜플은 내용이 고정돼 있어서 해시가 되니까 `{(37.57, 126.98): "서울"}`처럼 쓸 수 있어요. 리스트로 같은 걸 하면 `unhashable type: 'list'`라는 `TypeError`가 나요.
- **메서드:** 리스트엔 `append`, `insert`, `pop`, `remove`, `sort` 같은 수정용 메서드가 여럿 있고, 튜플엔 `count`와 `index` 두 개뿐이에요.
- **성능:** 튜플이 메모리를 조금 덜 쓰고 만드는 속도도 조금 빨라요. 리스트는 크기가 바뀌는 걸 감당해야 해서 그만큼 부가 비용이 붙거든요. 다만 차이가 작아서 이걸 보고 고를 일은 거의 없어요.

정확히 하자면 튜플에서 고정되는 건 '어떤 객체들을 담고 있느냐'까지예요. `t = ([1, 2], 3)`에서 `t[0].append(99)`는 문제없이 돼요. 튜플은 여전히 같은 리스트를 가리키고 있고, 바뀐 건 그 리스트의 내용이니까요. 대신 이런 튜플은 해시가 안 돼서 딕셔너리 키로는 못 써요.

쓰임새에도 관례가 있어요. 리스트는 회원 목록이나 점수들처럼 같은 종류의 값을 몇 개든 모아 둘 때 쓰고, 튜플은 `(x, y)` 좌표나 `(이름, 나이)`처럼 자리마다 의미가 정해진 묶음에 써요. 함수에서 `return a, b`로 값을 여러 개 돌려줄 때 실제로 넘어가는 것도 튜플이에요.

그런데 `return a, b`에는 괄호가 없죠. 튜플을 만드는 건 사실 괄호가 아니라 쉼표라서 그래요.

```python
a = 1, 2, 3    # 튜플 (1, 2, 3)
b = (5)        # 그냥 정수 5
c = (5,)       # 원소 하나짜리 튜플
```

괄호가 꼭 필요한 건 빈 튜플(`()`)을 만들 때, 그리고 `f((1, 2))`처럼 빼면 인자 두 개로 바뀌어 버리는 자리 정도예요. 그 밖에는 거의 장식인 셈이죠.
