아니요, 둘이 똑같은 건 양쪽 타입이 같을 때뿐이에요. 타입이 다르면 `===`는 바로 `false`를 돌려주지만, `==`는 값을 변환해서 타입을 맞춘 다음 비교해요. 문제는 그 변환 규칙이 꽤 엉뚱하다는 거예요.

```js
0 == ''            // true
0 == '0'           // true
'' == '0'          // false
false == '0'       // true
[] == false        // true
null == undefined  // true
```

`0`은 `''`와도 같고 `'0'`과도 같은데, 정작 `''`와 `'0'`은 서로 달라요. 코드를 볼 때마다 이걸 따지고 있을 수는 없잖아요.

실제로 터지는 건 이런 경우예요. 폼의 `input.value`는 항상 문자열이라서, `if (input.value == 0)`이라고 쓰면 빈칸(`''`)도 0인 것처럼 통과해요. 에러 없이 조용히 틀리니까 찾기도 어렵고요.

그러니까 기본은 `===`예요. 한 글자 아끼고 디버깅을 떠안는 건 남는 장사가 아니에요. 예외로 둘 만한 건 위 마지막 줄을 이용한 `x == null` 하나예요. `null`과 `undefined`를 한 번에 거르는 관용구로 널리 쓰이고, ESLint `eqeqeq` 규칙에도 이것만 허용하는 옵션(`{ "null": "ignore" }`)이 있어요. 그 규칙을 켜두면 나머지 `==`는 알아서 잡아줘요.
