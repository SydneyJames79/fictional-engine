괄호 모양만 다른 게 아니에요. 핵심은 바꿀 수 있느냐 없느냐예요. 리스트는 만든 뒤에도 원소를 추가·삭제·교체할 수 있고(mutable), 튜플은 한 번 만들면 그대로예요(immutable). 인덱싱, 슬라이싱, 반복처럼 읽기만 하는 동작은 둘 다 똑같이 돼요.

```python
a = [1, 2, 3]
a[0] = 10       # 가능
a.append(4)     # 가능

t = (1, 2, 3)
t[0] = 10       # TypeError: 'tuple' object does not support item assignment
```

여기서 실제로 쓸 때의 차이가 몇 가지 따라 나와요.

- 튜플은 딕셔너리 키나 세트 원소로 쓸 수 있고, 리스트는 못 써요. 딕셔너리는 키의 해시값으로 자리를 찾는데, 내용이 바뀔 수 있는 리스트는 해시값을 고정할 수 없어서 아예 막혀 있어요. `{(0, 0): "start"}`는 되지만 `{[0, 0]: "start"}`는 `unhashable type: 'list'`라는 `TypeError`가 나요.
- 리스트에는 `append`, `insert`, `remove`, `sort`처럼 내용을 바꾸는 메서드가 있지만, 튜플에는 `count`와 `index` 두 개뿐이에요.
- 튜플이 메모리를 조금 덜 써요. 리스트는 크기가 변하는 구조라 여유 공간과 관리용 정보를 더 들고 있거든요. 다만 속도 차이는 보통 체감할 정도가 아니라서, 성능 때문에 둘 중 하나를 고를 일은 거의 없어요.

헷갈리기 쉬운 점이 두 가지 있어요. 하나는 튜플의 불변성이 얕다는 거예요. 튜플이 어떤 객체를 담고 있는지가 고정될 뿐, 그 객체 자체가 얼어붙는 건 아니에요.

```python
t = ([1, 2], 3)
t[0].append(99)   # 에러 없음 → t는 ([1, 2, 99], 3)
t[0] = [5]        # TypeError (칸 자체를 바꾸는 건 안 됨)
```

이렇게 리스트가 들어 있는 튜플은 해시가 안 돼서 딕셔너리 키로도 못 써요. 앞에서 튜플을 키로 쓸 수 있다고 한 건, 안에 숫자나 문자열처럼 해시 가능한 값만 들어 있을 때 얘기예요.

다른 하나는, 튜플을 만드는 게 사실 괄호가 아니라 쉼표라는 거예요. `t = 1, 2, 3`도 튜플이고, `(1)`은 그냥 정수 1이에요. 원소가 하나인 튜플은 `(1,)`처럼 쉼표를 붙여야 하고, 괄호만으로 튜플이 되는 건 빈 튜플 `()`뿐이에요. 괄호 모양만 다르냐고 물었는데, 튜플은 그 괄호조차 본질이 아닌 셈이에요.

어느 쪽을 쓸지는 보통 이렇게 갈라요. 같은 종류의 항목을 모아 두고 개수가 늘거나 줄 수 있으면 리스트(사용자 목록, 파일에서 읽은 줄들), 자리마다 의미가 있는 고정된 묶음이면 튜플(`(x, y)` 좌표, 함수가 `return a, b`로 값 여러 개를 돌려줄 때)이에요. 언어가 강제하는 규칙은 아니지만, 튜플로 써 두면 읽는 사람도 "이건 바뀌지 않는 묶음이구나" 하고 바로 알아봐요.
