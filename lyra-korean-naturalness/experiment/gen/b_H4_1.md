아니요, 둘이 똑같이 동작하는 건 양쪽 타입이 같을 때뿐이에요. 평소엔 같은 타입끼리 비교할 때가 많으니 똑같아 보이는 거고요. 타입이 다르면 `===`는 거기서 바로 `false`인데, `==`는 값을 변환해서 타입부터 맞춘 다음 비교해요. 그런데 이 변환 규칙이 직관이랑 따로 놀아요.

```js
0 == ''            // true
0 == '0'           // true
'' == '0'          // false  ← 위 두 줄이 true인데도
'0' == false       // true   ← '0'은 truthy인데도
null == undefined  // true
```

이게 그냥 퀴즈용 예시가 아닌 게, 입력창 값은 항상 문자열이에요. `input.value == 0`이라고 쓰면 0을 입력했을 때도, 칸이 비어 있을 때도 `true`가 나와요. 0을 넣어서 테스트하면 잘 되니까 빈칸 버그는 놓치기 딱 좋죠. `===`였으면 0을 넣어도 안 맞아서 숫자로 바꿔야 한다는 걸 그 자리에서 알았을 거예요.

그러니까 `===`를 기본으로 쓰세요. `=` 한 글자 아끼자고 저 규칙을 다 외우고 다닐 순 없잖아요. 예외로 쓸 만한 건 `x == null` 하나예요. `null`과 `undefined`를 한 번에 걸러 주는 관용구라 이건 많이들 허용하고, ESLint `eqeqeq` 규칙에도 이 경우만 빼 주는 옵션(`"null": "ignore"`)이 있어요.
